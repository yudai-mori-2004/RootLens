# 契約・同意まわりの設計メモ

合意書・利用規約・プライバシーポリシーを「どの現場・どのビジネスモデルでも成立する」形へ育てるための検討ログ。実際の条文改訂に入る前の設計メモで、結論ではなく「次に着手するときの出発点」。

> 状態 (2026-07-15): **保留中**。口約束で先行したパイロットが動いているため、紙の同意書・規約改訂は後回し。現行の運用は下記「現在動いている運用」を参照。

## 現在動いている運用 (パイロット)

- 形態: 店に **1日あたり定額** を支払い、こちらが **ヘッドセットをレンタル** して、店のスタッフに装着して働いてもらう。
- 契約はまだ口頭。会う前に口約束でビジネスを開始したため、後から紙で難しい条件を説明するのは筋が違うと判断し、書面化は一旦保留。
- この形態は既存テンプレの labor-supply / data-cooperation のどちらとも少し違う (定額 + 機材レンタル)。将来モデルを整理するときに 3 つ目として扱う余地がある。

## 今日の到達点 (2026-07-15 の議論)

### 1. data-cooperation の合意書に 3 条を追加済み (commit b1ac993)

- **利用許諾** (第8/9条): アプリでアップロード = 内容確認済みの同意。乙に利用・複製・加工・第三者提供の許諾。
- **中止・削除** (第10/11条): 第三者提供前は削除可、提供後は回収義務なし。
- **請求権の不行使** (第11/12条): 適法に利用した分には訴えない。「適法に利用した分」「店自身の請求」に限定 (最判 R6.7.11 で一方的に不利な不起訴合意は無効になるため)。
- あわせて店主の編集を反映: 事前確認条項の削除、ぼかしは「手段を約束・結果は保証しない」、店名非公表に「許可なく」、スタッフ報酬を「負担軽減費」に (賃金性を薄める)。

### 2. 代理店 (紹介) は「締約代理」にしない

- 代理店に契約締結を代行させる (締約代理) と、**表見代理** (民法109/110/112条) で当社が知らない契約に縛られる。条件バラつき・スタッフ同意の実在も担保できない。
- 正解は **媒介・取次 + 当社の承諾で成立**。将来、紹介制度を再開する場合は「代理権の不存在 + 当社の承諾で成立」を明記する。
- ただし今回は「せいぜい10店・全部自分で赴く」ため、締約代理の議論自体が実務上は不要。

### 3. アプリ内同意と合意書は「前提モデルがズレている」

- アプリの利用規約 (terms-of-service) は **個人が家事を撮る v0.1.4 モデル** のまま: 販売されたら成功報酬 / 自宅・家事前提 / 撮影者=アップ者=報酬受領者が同一。
- data-cooperation は **店が契約・スタッフが店で撮影・録画時間で定額協力費**。報酬体系・主体・場所が食い違う。
- **噛み合っている部分**: 権利処理 (利用許諾・削除・ぼかし・データ帰属) は、今日足した合意書 第8-12条と規約 第7/9/12条がよく対応。ぼかしの「結果は保証しない」も一致。
- **実質的な不整合 (要修正)**: 削除デッドラインが 規約=「学習使用前」/ 合意書=「第三者提供前」。当社がコントロールできるのは第三者提供前まで。**規約を「第三者提供前」に寄せるのが正しい** (学習使用前は買い手側の工程で保証できない)。

### 4. プライバシーポリシーは既にほぼ主体非依存

- PP は「当社が扱うデータ」中心に書けていて、撮影者が個人か事業者かを限定していない。第9条で映り込んだ第三者を独立に扱えているのが良い。
- 直すなら「撮影者への報酬」(第3条) を「データ提供者への対価」に一般化する程度。

## 目指す設計: 主体非依存の「ラッパー」型同意

現場の合意の中身を外部化し、アプリは「合意がある」ことの表明保証 + データ利用許諾だけを取る。3層に分ける:

```
現場合意層 (外部化・主体依存)
  個人=家族の同意 / 店=合意書+撮影同意書 / 将来の現場=その現場で成立
        ↑ アプリは中身を知らない
アプリ内同意層 (ラッパー・主体非依存)
  ① 表明保証「必要な現場合意を得ている」
  ② 利用許諾「当社にAI学習用の利用許諾を与える」
  ③ 一般禁止「違法・第三者の権利を侵す撮影はしない」
  → 報酬・場所・主体を書かない (報酬は外部参照)
プライバシーポリシー層 (公開・主体非依存)
  当社が扱うデータ + 映り込んだ第三者の権利
```

### 単純に行かない4点 (抽象化しきれない)

1. 表明保証は「第三者への免責」にならない。映り込んだ第三者に訴えられれば当社も被告になりうる。外部への盾は結局 **顔ぼかし + 検知除外** (技術)。
2. 現場ごとにリスクが違う (家庭=子ども・浴室、店=相対的に安全)。一般条項 + 現場個別条項の二段が要る。
3. 越境提供 (個情法28条) は映り込んだ本人の同意が要る。現場合意層で取る (撮影同意書に国外提供を明記)。
4. 同意する主体を運用で固定する必要 (店モデルなら店アカウントで店が表明保証)。

## 登場人物 (役割) の整理

日本の書面のセオリー: 契約当事者だけを甲乙 or 定義語で呼び、署名しない関係者は定義語で指す。当事者はむやみに増やさない。甲乙は文書ごとのローカルな指示語 (合意書では甲=店・乙=当社、紹介合意書では甲=紹介元・乙=当社)。

**Ⅰ. 契約当事者になりうる者**

| 普遍呼称 | 定義 | 法定語 |
|---------|------|-------|
| 当社 (RootLens) | 収集・加工・提供・販売する者 | 個人情報取扱事業者 |
| データ提供者 | アップロードし利用許諾を与える者 | (規約上の利用者) |
| 紹介元 | 撮影協力先を紹介する者 | (媒介者・非当事者) |

**Ⅱ. 定義語で指す、契約外の関係者**

| 普遍呼称 | 定義 | 法定語 |
|---------|------|-------|
| 撮影対象者 | 装着し意図して撮影される者 | 本人 |
| 映り込んだ第三者 | 撮影対象者以外で映る者 | 本人・第三者 |
| └ 未成年者・要配慮情報の本人 | 特別扱いを要する者 | 要配慮個人情報の本人 |
| 撮影場所の管理者 | 撮影場所を管理する者 | (施設管理権者) |
| 撮影者 | 現に撮影を行う者 | — |
| データ購入者 | 当社から提供を受ける者 | 第三者 (提供先) |
| 二次取得者 | データ購入者から更に提供を受ける者 | 第三者 |
| 委託先 | データ取扱いを委託する者 (R2・Modal 等) | 委託を受けた者 (法25条) |

**Ⅲ. 独立の当事者にせず、データ提供者 (甲) の属性・義務として書く**

- 撮影協力費の受領・配分 (甲の属性)
- 撮影同意書の作成・保管 (甲の義務)

**役割は不変、人への割り当てだけが変わる** (個人=全部本人に集約 / 店=撮影対象者と撮影者がスタッフ、場所管理者と提供者と受領者が店)。これが主体非依存インターフェースの根拠。
