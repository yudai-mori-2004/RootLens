# RootLens 法務文書 (legal/)

RootLens のデータ収集・販売に関する法務文書を集約する参照ハブ。各文書は**文書ごとのフォルダ**を持ち、その中に **`ja.md`(正)** と **`en.md`(対訳ミラー)** を配置する。

## 構成規約

```
document/v0.1.3/legal/
├── README.md                # 本ファイル(参照ハブ)
└── <doc-slug>/
    ├── ja.md                # 日本語(正本)
    └── en.md                # 英語(ミラー)
```

- **`ja.md` を正本**とし、`en.md` は対訳ミラー。両者が食い違う場合は `ja.md` を優先し、`en.md` を同期させる。
- 文書を更新したら、両言語と本 README の一覧・状態を同時に更新する。
- 対外文書(プライバシーポリシー・ToS 等)は両言語が等しく必要。社内文書は `ja.md` 先行で可、英訳は調達・監査の必要に応じて追従。

### 提示方式の規約(層化同意)

すべての**対ユーザー同意文書**(`tester-consent` / `privacy-policy` / `terms-of-service`)は、**要約のみ提示**にしない。次の層化構造を必須とする。

1. **層1 = 要約(非拘束)**: 主婦等にも分かる平易語。理解のためで、それ自体に拘束力はない。
2. **層2 = 正本全文(拘束)**: 実際に同意の対象となる完全な文。画面から常時アクセス可能にする。
3. 「要約は要約に過ぎず、**拘束するのは全文。食い違えば全文が優先**」と明記し、同意は全文に対して成立させる。
4. 同意時に、**同意した正本の版+ハッシュ**と**表示した要約の版+ハッシュ**を記録する([`consent-log-spec`](consent-log-spec/ja.md))。

理由: 要約のみだと(a)全文が契約に取り込まれない、(b)要約が拘束的表示になり不実表示リスク、(c)クリックラップの有効性が弱い。層化は GDPR の layered notice とも整合。

## 確定判断サマリ(詳細は `legal-policy`)

| ID | 判断 | 状態 |
|----|------|------|
| D1 | 適法化根拠は**同意主軸**、匿名化は補助層 | 確定 |
| D2 | **音声を記録する**(全当事者同意州はハード除外、声紋を識別子扱い) | 確定(承認済) |
| D3 | **識別可能な第三者が映ったクリップは販売除外** | 確定 |
| D4 | **児童・違法・私的空間は受容しない**(警告でなくブロック) | 確定 |
| D5 | 対外文書で**「匿名化済み」と表示しない** | 確定 |
| D6 | 削除・撤回の範囲を**正直に開示**(学習前は削除可/学習後は新規学習除外) | 確定 |
| D7 | **全世界目標・日本先行の段階展開** | 確定(承認済) |
| D8 | 残存リスクの台帳受容 + 保険 | 保留(空欄) |

合法性の背骨は**同意**であって匿名化ではない(類似事業者は匿名化に賭けているが、当社は動画本体+ラベルを売るため成立しない)。「同意も信頼できる匿名化も無いものは販売ルートに到達させない」が原則。

## 公開タイミングの段階(front-load しない)

| 種類 | トリガー | 例 |
|------|----------|----|
| 社内の判断記録 | **今から**持って育てる(公開しない。調達 diligence 資料) | `legal-policy` |
| 対外の同意・通知 | **他人のデータを集めた瞬間=もう必要**(アルファでも軽量で) | `tester-consent` → `privacy-policy` / `terms-of-service` |
| 重い装置 | **販売・本番公開・EU進出・スケール**が来てから | `dpia` / `buyer-license` / `cross-border-transfer` / `ropa` |

現ステージ(アルファ・TestFlight 収集中・未登記・調達準備)での優先は、(1) `tester-consent`(軽量同意+撮影ルール)→ (2) 会社登記 + IP 帰属 → (3) スポット弁護士(登記・トークン証券性)。重い装置は触らない。
