# 同意記録設計 (consent-log-spec)

**種別**: 仕様(社内) / **状態**: ドラフト / **言語**: ja(正本。en は調達・監査の必要時に追従)

「**誰が・いつ・どの文書のどの版に・何のスコープで同意/撤回したか**」を後から証明できるようにするための記録仕様。説明責任原則([`legal-policy`](../legal-policy/ja.md) §6 ④証明)と、層化同意の有効性(要約ではなく**正本全文**に同意したことの立証)を支える。実装はこの仕様を参照して同意フローを作る。

## 1. 目的

- 同意の**有効性**を立証する(特定・情報提供・自由・撤回可能)。
- 層化同意で「**正本全文に同意した**」ことと「**何の要約を見せたか**」を両方残す。
- 文書改定後も、各同意が**当時の版**に紐づくようにする。
- 撤回とその効果範囲を追跡する。

## 2. 記録の単位 = 同意イベント

同意・再同意・撤回のたびに 1 イベントを append-only で記録する。最低フィールド:

| フィールド | 内容 |
|------------|------|
| `event_id` | 一意ID |
| `event_type` | `consent` / `reconsent` / `withdrawal` |
| `subject_id` | テスター/ユーザー識別子(ウォレット公開鍵 または ユーザーID) |
| `occurred_at` | 発生時刻(UTC) |
| `doc_slug` | 対象文書(`tester-consent` / `privacy-policy` / `terms-of-service` 等) |
| `doc_version` | 同意した**正本全文**のバージョン |
| `doc_content_hash` | 正本全文の SHA-256(改竄検知・「どの文面に同意したか」の証跡) |
| `summary_version` | 画面に表示した**要約(層1)**のバージョン |
| `summary_hash` | 要約の SHA-256(「何を見せたか」の証跡) |
| `scopes` | 同意スコープの配列(`collection` / `ai_training_use` / `license_sale` / `cross_border`) |
| `checkbox_results` | 各チェック項目(例: `age18`, `no_third_party`, `agree_terms`)の真偽 |
| `locale` | 表示言語(`ja` / `en`) |
| `consent_method` | 取得方式(`clickwrap` 等) |
| `app_version` / `device` | アプリ・端末情報 |
| `ip` / `user_agent` | 任意(GDPR 系では最小化に留意) |
| `signature` | 任意。ウォレット ed25519 等で署名する場合の署名値 |

## 3. 撤回の記録

撤回も同じ仕組みで `event_type=withdrawal` として記録する。`scopes` で部分撤回を表現可能。撤回の効果(未学習データの削除/学習後は新規学習除外)は [`privacy-policy`](../privacy-policy/ja.md) §10–11 と [`tester-consent`](../tester-consent/ja.md) §3.5 に従う。

## 4. 文書バージョン管理

- `legal/` の各文書は**バージョン**と**全文ハッシュ**を持つ(改訂履歴に記録)。
- 文書を改定したら新バージョンとし、**過去の同意は過去の版**に紐づいたまま不変とする。
- 表示する要約(層1)も独立にバージョン管理し、ハッシュを残す。

## 5. 改竄耐性

- append-only(更新・削除を許さない)。
- 望ましくはハッシュチェーンまたは署名で連結。
- サーバ側に保存。必要に応じてオンチェーンには**ハッシュ等の記号のみ**を置き、**同意ログ本体(個人データ)はオンチェーンに載せない**([`legal-policy`](../legal-policy/ja.md) の方針)。

## 6. 取扱い上の注意

- 同意ログ自体が**個人データ**であり、保護・保持期間管理の対象。
- `doc_content_hash` / `summary_hash` の算出対象(正規化方法・対象範囲)を実装で固定し、文書側の改訂履歴と一致させる。

## 7. 連携

- [`tester-consent`](../tester-consent/ja.md) §4、[`privacy-policy`](../privacy-policy/ja.md) §0/§15 が本仕様を参照。
- 実装の現状: ライセンス/ステークが多くモックのため、同意ログも未実装の可能性が高い(実装監査参照)。本仕様を先に確定し、実装はこれを正典とする。
