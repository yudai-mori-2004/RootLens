# RootLens UX 仕様書

## 0. この文書について

本仕様書は、RootLens iOS アプリのユーザーインターフェースと操作体験の設計を定義する。ユーザーがアプリを開いてから、動画を撮影し、スコアを確認し、ステーキングを判断するまでの全体験を扱う。

データパイプラインの技術仕様（センサーフォーマット、品質スコアリング、データセット組み立て等）はデータパイプライン仕様書を参照すること。

---

## 1. 設計原則

### 1.1 ヘッドマウント特化

RootLens の撮影はスマートフォンをヘッドマウントに装着して行う。装着中ユーザーは画面を見ることもタッチすることもできない。一度装着したら、ヘッドマウントを外さずに複数の撮影を連続して完了させる。

画面タッチが許容されるのは、装着前の準備と、取り外した後の確認・管理（ホームタブでのスコア確認・ステーキング）のみ。

### 1.2 入出力チャンネル

ヘッドマウント装着中の入出力は以下に集約する。

- **ジェスチャー（入力）**: カメラに映る手の形でユーザーの意思を表現する。手のひら上向き（撮影開始）、サムズアップ（撮影終了）の 2 種のみ。
- **音声ガイド（出力）**: TTS によるアプリからの案内・フィードバック。状態遷移の説明、キャリブレーション指示、撮影後の次タスク提案を音声で伝える。
- **効果音（出力）**: ジェスチャー検出、カウントダウン、録画開始・停止、警告等の短い音。音声ガイドを補助する。

ユーザーからの音声入力（ウェイクワード、STT、対話）は採用しない。ヘッドマウント装着中に話しかけて聞き取られない体験は、画面での text fallback も使えない状況では取り返しがつかないストレスになる。

### 1.3 タスクは事前選択しない

ユーザーは撮影前に「これから何を撮るか」をアプリに入力しない。「掃除しようかな、撮り始める」のように、自分の活動を撮るだけで、何のタスクだったかは Pipeline 2 の VLM ラベリングが事後的に分類する。

事前選択を求めない理由は 2 つ。第一に、ヘッドマウント装着前に画面に触ってタスクを選ぶ動線が UX 上の摩擦になる。第二に、事前申告と実映像のズレを検査する仕組みは Pipeline 2 のラベリングと役割が重複する。ラベルは事後で良い。

ユーザーには「こんな活動が撮れます」のインスピレーション例だけを提示する（掃除 / 洗濯 / 料理 / 勉強等）。撮影フローには介入しない。

### 1.4 撮影開始時キャリブレーション

ヘッドマウント装着の角度はユーザーごとに異なる。毎回の撮影開始ジェスチャー（手のひら上向き）の際に、リラックスして手元に視線を向けた状態でのフレーム内の手の位置をキャリブレーションする。

キャリブレーションは独立した工程ではなく、撮影開始の儀式に自然に組み込まれている。

### 1.5 使用カメラ

超広角（Ultra Wide）カメラを固定で使用する。エゴセントリック撮影では両手の作業領域を広く捉える必要があり、標準画角（1x）では不十分。画面の向きは横向き（landscape）に固定する。

### 1.6 モード遷移には音を鳴らす

ヘッドマウント装着中、音声ガイドと効果音が唯一の状態認識手段。モード遷移と状態変化は必ず音で伝える。

## 2. アプリ構造

### 2.1 全体構成

アプリは 3 つのフッタータブで構成される。

```
┌─────────────────────────────────┐
│                                 │
│         コンテンツ領域            │
│                                 │
├──────────┬──────────┬───────────┤
│  ホーム   │  カメラ   │   設定    │
│   (左)    │  (中央)   │   (右)    │
└──────────┴──────────┴───────────┘
```

- **ホーム（左）**: コレクション管理、ステーキング、収益確認。アプリ起動時のデフォルト表示。
- **カメラ（中央）**: 撮影モードへの入口。押下すると撮影モードに入る。
- **設定（右）**: アカウント、撮影設定、アプリ情報。

### 2.2 撮影モード

カメラボタンを押すと撮影モードに入る。フルスクリーンカメラプレビュー + ハンドトラッキングオーバーレイが表示され、音声ガイドが「リラックスして手のひらを見てください」と案内する。

撮影モード内では、以下のループが繰り返される。

```
[手のひら上向き → キャリブレーション → カウントダウン → 録画]
    → [サムズアップ → カウントダウン → 録画停止 → 次タスク提案]
    → [手のひら上向き → ...]  （ループ）
```

ヘッドマウントを外さずに複数クリップを連続撮影できる。撮影モードから抜けるには、ヘッドマウントを外して画面の戻るボタンをタップする。

## 3. ホームタブ

### 3.1 概要

ホームタブはアプリ起動時のデフォルト画面で、撮影済みクリップの管理と収益確認を行う。ヘッドマウントを外した状態で、画面をタッチして操作する通常の GUI。

### 3.2 コレクション一覧

クリップのカード一覧を表示する。各カードはサムネイル（ぼかし済み映像の代表フレーム）と状態バッジを持つ。

| 状態 | バッジ表示 | カードタップ時の動作 |
|------|----------|-------------------|
| アップロード中 | 進捗バー | アップロード詳細（キャンセル可能） |
| アップロード失敗 | オレンジバッジ「再試行」 | リトライ + 削除 |
| 処理中 | スピナー + 現在ステップ名 | 処理詳細（待機のみ） |
| ready | 緑バッジ「準備完了」 | クリップ詳細画面（§3.3） |
| staked | 紫バッジ「ステーキング中」 | クリップ詳細画面（§3.4） |
| 処理エラー | 赤バッジ「エラー」 | エラー詳細 + サポート連絡 |

一覧はデフォルトで撮影日時の降順。フィルタ（状態別）とソート（スコア順）を切り替え可能。

### 3.3 クリップ詳細画面（ready 状態）

**プレビュー**: ぼかし済み映像の代表フレーム。ぼかしの適切さを確認できる。

**自動分類ラベル**: Pipeline 2 の VLM ラベリングが付与したカテゴリ（掃除 / 洗濯 / 料理等）と行動説明。

**品質スコア**: 総合スコア（0〜100）と全サブ指標の内訳。各指標に短い説明テキストを添える。

**撮影情報**: 撮影日時、撮影時間、デバイス情報。

**アクション**: 「ステーキングする」ボタン → ステーキング確認シート（§3.5）。「削除する」ボタン → 削除確認ダイアログ。

### 3.4 クリップ詳細画面（staked 状態）

§3.3 と同じ情報に加え、ステーキング日時、発行済み License NFT 数、累積収益を表示する。

**アクション**: 「アンステークする」ボタン → アンステーク確認ダイアログ（既発行 License NFT がある場合は「既発行のライセンスは永続します」の注意喚起を含む）。

### 3.5 ステーキング確認シート

クリップ詳細画面から呼び出される確認シート。以下を表示する。

1. **ぼかし済みプレビュー**: ぼかしの確認を兼ねる。
2. **品質スコアと内訳**。
3. **想定報酬レンジ**: 品質スコアと自動分類カテゴリに基づく試算。
4. **撤回不能性の注意喚起**: 「License NFT が 1 つでも発行された後は撤回できません。ステーキングを解除しても既発行のライセンスは永続します。」チェックボックスで確認。
5. **ステーキング実行ボタン**: チェック済みでないと非活性。押下後に最終確認ダイアログ（二段階確認）。

### 3.6 収益セクション

- **未引き出し残高**: 全 Root NFT の累積未分配収益合計（USDC）。
- **引き出しボタン**: `claim_revenue` を実行。
- **収益履歴**: License NFT 発行ごとの記録（日時、金額、対応クリップのサムネイル）。

## 4. 撮影モード

### 4.1 進入

フッター中央のカメラボタンを押すと撮影モードに入る。進入時に効果音を鳴らす。

画面全体が超広角カメラのフルスクリーンプレビューで占められる。画面の向きは横向き（landscape）固定。ハンドトラッキングオーバーレイが手の検出時にスケルトンを描画する。

```
┌──────────────────────────────────────────┐
│ [←]                                      │
│                                          │
│       フルスクリーン                       │
│       超広角カメラプレビュー                │
│       + ハンドトラッキングオーバーレイ      │
│                                          │
│                                          │
│                                          │
└──────────────────────────────────────────┘
```

進入直後、音声ガイドが「リラックスして手のひらを見てください」と案内する。

### 4.2 撮影開始シーケンス

撮影開始は以下のシーケンスで進行する。誤操作防止のため、約 5 秒間の意図的なジェスチャー保持を要求する。

**Step 1: 手のひら上向き検出**

ユーザーが両手の手のひらを上に向けた状態を取る。Apple Vision で両手の手ランドマークが検出され、手のひらが上向きであることが判定される。

1 秒間安定して検出されると、検出音（ピコン）が鳴る。

> 手の甲をカメラに向ける姿勢では手首が指を隠す角度になりやすいため、手のひらを上に向ける姿勢を採用した。

**Step 2: キャリブレーション**

検出音の直後、フレーム内での両手の位置を確認する。

- 両手がフレーム中央付近に収まっている場合: キャリブレーション成功。両手のフレーム内位置（中心座標、分散、bbox サイズ）を baseline として保存する。
- 手が中央から大きくずれている場合: 音声ガイドで調整を案内する（「カメラをもう少し下に向けてください」「少し上を向けてください」等）。ユーザーがヘッドマウントの角度を微調整し、再度手のひら上向きを 1 秒保持すると再判定する。

キャリブレーションの baseline は、録画中の「手がフレームに映っているか」判定の基準値として使用する。

**Step 3: 音声案内 + カウントダウン**

キャリブレーション成功後、音声ガイドが「そのまま手のひらを上に向けてキープ。撮影を開始します」と案内する。

音声案内に続いて、カウントダウン音が鳴る（テテテ、ピー）。カウントダウン完了で録画が開始される。録画開始音が鳴る。

Step 1 の検出からカウントダウン完了まで約 5 秒。この間ずっと手のひら上向きを保持する必要がある。途中で手を下ろした場合は Step 1 からやり直しになる。

### 4.3 録画中

録画中の操作はサムズアップによる停止のみ。

**手フレームアウト警告**: キャリブレーション済みであれば、通常の作業姿勢で両手はフレーム内に収まる。両手ともフレームから外れた状態が 5 秒間継続した場合に限り、音声ガイドで警告する（「手がカメラに映っていません」）。警告は手が戻るまで一定間隔で繰り返す。

**録画時間上限**: 60 分で自動停止する。停止時に音声ガイドで「録画時間の上限に達しました」と通知する。

**録画インジケーター**: 画面右上に赤い ● REC マークと経過時間を表示する。

### 4.4 撮影終了シーケンス

**Step 1: サムズアップ検出**

両手のサムズアップを 1 秒間検出すると、検出音が鳴る。

**Step 2: 音声案内 + カウントダウン**

音声ガイドが「そのままキープ。撮影を終了します」と案内する。続いて 3 カウントのカウントダウン音が鳴り、カウントダウン完了で録画が停止する。停止音が鳴る。

途中でサムズアップを解除した場合、録画は継続する（誤操作防止）。

**Step 3: 最低録画時間チェック**

録画時間が n 秒未満（開発時初期値: 1 秒）のクリップは、クライアント側で自動破棄する。アップロードもパイプライン処理も行わない。

### 4.5 クリップ完了と次タスク提案

録画停止後、プライバシー処理（顔ぼかし）+ C2PA 署名 + アップロードがバックグラウンドで自動開始される。ユーザーへの確認ダイアログは出さない（ヘッドマウント中で操作不可能なため）。

アップロード開始後、音声ガイドが次の撮影を自然に促す。

```
音声: 「お疲れさま、クリップ完了。
       次は洗濯物畳みとか、食器の片付けとかどうですか？
       手のひらを上に向けると撮影が始まります。」
```

次タスクの提案内容は、終了直後のフレームを VLM（Haiku）に 1 枚送って直前の活動を推定し、それと異なるカテゴリの活動を提案する。VLM 呼び出しが失敗した場合や応答が遅い場合は、活動例リストからランダムに提案する。コストは 1 クリップあたり約 $0.001。

ユーザーは次の手のひら上向きジェスチャーで、すぐに次のクリップの撮影に入れる（§4.2 に戻る）。

### 4.6 撮影モードの操作まとめ

| 操作 | 手段 | 動作 |
|------|------|------|
| 撮影開始 | 手のひら上向き 約 5 秒 | キャリブレーション → カウントダウン → 録画開始 |
| 撮影終了 | サムズアップ 約 4 秒 | カウントダウン → 録画停止 → 自動アップロード |
| 撮影モード終了 | ヘッドマウントを外して画面の戻るボタンをタップ | ホームタブへ戻る |

## 5. 音の設計

### 5.1 音声ガイド

アプリからの案内は音声ガイド（TTS）で行う。AVSpeechSynthesizer を使用する。音声ガイドは以下のタイミングで発話する。

| タイミング | 音声内容（例） |
|----------|------------|
| 撮影モード進入 | 「リラックスして手のひらを見てください」 |
| キャリブレーション調整 | 「カメラをもう少し下に向けてください」 |
| 撮影開始前 | 「そのまま手のひらを上に向けてキープ。撮影を開始します」 |
| 手フレームアウト警告 | 「手がカメラに映っていません」 |
| 録画時間上限 | 「録画時間の上限に達しました」 |
| 撮影終了前 | 「そのままキープ。撮影を終了します」 |
| クリップ完了 | 「お疲れさま、クリップ完了。次は〇〇とかどうですか？」 |

音声ガイドの文言は固定テンプレートではなく、状況に応じて自然な表現を使う。ただしユーザーからの音声入力は受け付けない。

### 5.2 効果音一覧

効果音は短く（0.5〜2 秒）、互いに聞き分けられるように設計する。効果音はあくまで音声ガイドの補助であり、効果音だけで状態を判別することは求めない。

| タイミング | 音の種類 |
|----------|---------|
| 撮影モード進入 | 上昇トーン |
| 手のひら上向き検出（1 秒） | ピコン（検出音） |
| キャリブレーション成功 | 確定トーン |
| カウントダウン（開始時） | テテテ、ピー |
| 録画開始 | 開始音 |
| 手フレームアウト警告 | 警告音（一定間隔で繰り返し） |
| サムズアップ検出（1 秒） | ピコン（検出音） |
| カウントダウン（終了時） | 3 カウント音 |
| 録画停止 | 停止音 |
| アップロード開始 | 送信音 |
| アップロード失敗 | エラートーン |
| 撮影モード終了 | 下降トーン |

### 5.3 BGM

撮影中の BGM 再生は採用しない。キャリブレーション前提で手は基本的にフレーム内に収まるため、BGM フェードによるフィードバックは不要。BGM が欲しい場合は端末の OS 機能（ミュージックアプリ等）で別途再生する。AudioSession は mixWithOthers で他アプリの音を阻害しない。

## 7. オンボーディング

### 7.1 初回起動フロー

1. **ウェルカム画面**: RootLens の概要説明（3 枚のカルーセル）。「ヘッドマウントに装着してジェスチャーだけで撮影できます」等の要点。
2. **KYC**: 第三者 KYC サービスへの遷移。完了するまで撮影機能はロック。
3. **利用規約同意**: 利用規約の 7 項目サマリを表示し、全文スクロール + チェックボックスで同意を取得する。サマリの内容と利用規約本文の仕様はライセンス仕様書で定義する。
4. **カメラ権限**: OS の権限ダイアログ。なぜ必要かの事前説明画面を挟む。マイク権限は要求しない。
5. **チュートリアル（スキップ不可）**: 初回のみ、撮影モードに入った際にインタラクティブなチュートリアルを実行する。ヘッドマウント装着 → 手のひら上向き → キャリブレーション → カウントダウン → 短い練習録画 → サムズアップ → 終了、を 1 周流す。

### 7.2 撮れる活動の例

オンボーディング末尾、およびホームタブの空状態（クリップ 0 件時）に、「こんな活動が撮れます」のインスピレーション例を表示する。掃除 / 洗濯 / 料理 / 勉強 / 工作 / 整理整頓等を写真付きで提示する。

これはタスク選択ではなく、「こういう活動なら撮ってデータとして売れる」という発見のヒント。実際の撮影では事前申告なしで撮影でき、Pipeline 2 が事後的に分類する。

### 7.3 ToS 更新時

ToS の新バージョンが発行された場合、次回アプリ起動時に §7.1 のステップ 3 のみを再実行する。新バージョンに同意するまで撮影機能はロック。
