# RootLens UX 仕様書

## 0. この文書について

本仕様書は、RootLens iOS アプリのユーザーインターフェースと操作体験の設計を定義する。ユーザーがアプリを開いてから、動画を撮影し、スコアを確認し、ステーキングを判断するまでの全体験を扱う。

データパイプラインの技術仕様（センサーフォーマット、品質スコアリング、LeRobot 組み立て等）はデータパイプライン仕様書を参照すること。

---

## 1. 設計原則

### 1.1 ヘッドマウント前提の設計

RootLens の撮影はスマートフォンをヘッドマウントまたはネックストラップに装着して行う。この状態でユーザーは画面を見ることもタッチすることもできない。したがって、撮影中の一切の操作は音声とジェスチャーで完結しなければならない。

画面タッチが許容されるのは、ヘッドマウント装着前の準備と、取り外した後の確認・管理のみである。

### 1.2 3 つの入出力チャンネル

ヘッドマウント中にユーザーが使える入出力は以下の 3 つだけである。

- **音声（入力）**: ウェイクワード「ヘイレンズ」で AI エージェントを起動し、自然言語で対話する。
- **ジェスチャー（入力）**: カメラに映る手の形で操作する。オープンパーム（撮影開始）、サムズアップ（撮影終了）。
- **音（出力）**: BGM、効果音、AI の音声応答。状態遷移、フィードバック、エラーのすべてを音で伝える。

### 1.3 モード遷移には必ず音を鳴らす

ヘッドマウント中、音は唯一の状態認識手段である。すべてのモード遷移・状態変化に固有の音を割り当て、ユーザーが音だけで「今アプリが何をしているか」を判別できるようにする。

## 2. アプリ構造

### 2.1 全体構成

アプリは 3 つのフッタータブで構成される。

```
┌─────────────────────────────────┐
│                                 │
│         コンテンツ領域            │
│                                 │
├──────────┬──────────┬───────────┤
│  ホーム   │  カメラ   │   設定    │
│   (左)    │  (中央)   │   (右)    │
└──────────┴──────────┴───────────┘
```

- **ホーム（左）**: コレクション管理、ステーキング、収益確認。アプリ起動時のデフォルト表示。
- **カメラ（中央）**: 撮影モードへの入口。押下すると撮影モードに入る。
- **設定（右）**: アカウント、通知、デバイス設定。

### 2.2 撮影モードの内部構造

カメラボタンを押すと撮影モードに入る。撮影モードは 2 つのサブモードを持つ。

```
撮影モード
  ├─ 対話サブモード   ← カメラボタン押下で最初にここに入る
  │    音声で AI と対話。タスク選択、撮影基準の確認。
  │    カメラプレビューは常時表示、ハンドトラッキングも動作。
  │
  └─ カメラサブモード  ← タスク確定後に遷移
       録画中。操作はジェスチャーのみ、音声操作は無効。
       BGM による手のフレームインフィードバック。
```

対話サブモードとカメラサブモードは、ヘッドマウントを外さずにループできる。カメラサブモードで撮影が完了すると、対話サブモードに戻り「次のタスクはある？」と AI が聞く。ユーザーは音声で次のタスクに進むか、撮影モード自体を終了できる。

撮影モードから抜けると、ホームタブに戻る。

## 3. ホームタブ

### 3.1 概要

ホームタブはアプリ起動時のデフォルト画面であり、撮影済みクリップの管理と収益確認を行う。ヘッドマウントを外した状態で、画面をタッチして操作する通常の GUI である。

### 3.2 コレクション一覧

画面上部にクリップのカード一覧を表示する。各カードはサムネイル（ぼかし済み映像の代表フレーム）と状態バッジを持つ。

状態バッジはデータパイプライン仕様書 §6 のクリップ状態機械に対応する。

| 状態 | バッジ表示 | カードタップ時の動作 |
|------|----------|-------------------|
| アップロード中 | 進捗バー | アップロード詳細（キャンセル可能） |
| アップロード失敗 | オレンジバッジ「再試行」 | リトライボタン + 削除ボタン |
| 処理中 | スピナー + 現在ステップ名 | 処理詳細（待機のみ） |
| ready | 緑バッジ「準備完了」 | クリップ詳細画面（§3.3） |
| staked | 紫バッジ「ステーキング中」 | クリップ詳細画面（§3.4） |
| 処理エラー | 赤バッジ「エラー」 | エラー詳細 + サポート連絡 |

一覧はデフォルトで撮影日時の降順。フィルタ（状態別）とソート（スコア順）を切り替え可能。

### 3.3 クリップ詳細画面（ready 状態）

ready 状態のカードをタップすると、クリップ詳細画面に遷移する。以下の情報を表示する。

**プレビュー**: ぼかし済み映像の代表フレーム数枚。ユーザーはぼかしが適切に適用されているかを確認できる。

**品質スコア**: 総合スコア（0〜100）と、全サブ指標の内訳。各指標にはその意味を示す短い説明テキストを添える。ユーザーが「なぜこのスコアになったか」を理解し、次回の撮影改善に活かせるようにする。

**タスク情報**: 撮影したタスク名、撮影日時、撮影時間、デバイス情報。

**アクション**:
- 「ステーキングする」ボタン → ステーキング確認シート（§3.5）を表示
- 「削除する」ボタン → 削除確認ダイアログ

### 3.4 クリップ詳細画面（staked 状態）

staked 状態のカードをタップすると、§3.3 と同じ情報に加えて以下を表示する。

- ステーキング日時
- このクリップから発行された License NFT の数
- このクリップからの累積収益

**アクション**:
- 「アンステークする」ボタン → アンステーク確認ダイアログ（既発行 License NFT がある場合は「既発行のライセンスは永続します」の注意喚起を含む）

### 3.5 ステーキング確認シート

クリップ詳細画面から呼び出される確認シート（ボトムシートまたはモーダル）。ステーキング実行前の最終確認として以下を表示する。

1. **ぼかし済みプレビュー**: 代表フレーム。ぼかしの確認を兼ねる。
2. **品質スコアと内訳**: §3.3 と同一。
3. **想定報酬レンジ**: 品質スコアとタスク種別に基づく試算。
4. **撤回不能性の注意喚起**: 「このクリップについて License NFT が 1 つでも発行された後は、撤回はできません。ステーキングを解除しても既発行のライセンスは永続します。」チェックボックスで確認を求める。
5. **ステーキング実行ボタン**: チェックボックスが入っていないと非活性。押下後にさらに最終確認ダイアログを 1 つ出す（二段階確認）。

ステーキング実行は Bubblegum の delegate 命令により Root NFT の delegate を RootLens のアドレスに設定する。ユーザーの署名が必要。

### 3.6 収益セクション

コレクション一覧の下部、またはタブ切り替えで表示する。

- **未引き出し残高**: 全 Root NFT の累積未分配収益合計（USDC）。
- **引き出しボタン**: `claim_revenue` を実行し、全残高をユーザーのウォレットに送金する。
- **収益履歴**: License NFT 発行ごとの収益記録（日時、金額、対応クリップのサムネイル）。

## 4. 撮影モード: 対話サブモード

### 4.1 進入

フッター中央のカメラボタンを押すと、撮影モードに入り、対話サブモードが開始する。進入時に固有の効果音を鳴らす。

### 4.2 画面レイアウト

画面全体がカメラプレビューで占められる。カメラサブモードとの視覚的な断絶がなく、対話中もカメラサブモードも同じ画面の上で動作する。画面の向きはデバイスの物理的な向きに動的に追従し、基本は横向き（landscape）。

```
┌──────────────────────────────────────────┐
│ [←]                                [≡]  │
│                                          │
│  ┌─────────────────────────────────┐     │
│  │ AI: 洗い物のタスクがあります。    │     │  ← 上部: AI 応答（トースト、数秒で消える）
│  │     撮影基準を確認しますか？      │     │
│  └─────────────────────────────────┘     │
│                                          │
│          フルスクリーン                    │
│          カメラプレビュー                  │
│          + ハンドトラッキングオーバーレイ    │
│                                          │
│                                          │
│  ┌─────────────────────────────────┐     │
│  │ 🎙 「基準教えて」                │     │  ← 下部: ユーザー発話（トースト、数秒で消える）
│  └─────────────────────────────────┘     │
└──────────────────────────────────────────┘
```

**ヘッダー**: カメラプレビュー上にオーバーレイで半透明表示。左に戻るボタン、右にハンバーガーメニュー（タスクリスト手動選択用）。操作がない間はフェードアウトしてプレビューを邪魔しない。

**AI 応答（上部トースト）**: AI の応答テキストが画面上部にトースト形式でポップアップし、数秒後にフェードアウトする。複数の応答が連続する場合はスタックして表示される。

**ユーザー発話（下部トースト）**: ユーザーの発話が STT でテキスト化され、画面下部にトースト形式で表示される。聞き取り中はマイクインジケータが点灯する。

**ハンドトラッキング**: カメラプレビュー上に手のスケルトンをオーバーレイ描画する。対話サブモードでもカメラサブモードでも同じ描画が維持される。

### 4.3 マウント案内

対話サブモードに初めて入ったとき、AI が音声で「ヘッドマウントまたはネックストラップに装着してください。準備ができたら『ヘイレンズ』と話しかけてください」と案内する。同じ内容が上部トーストにも表示される。

### 4.4 音声対話フロー

ユーザーが「ヘイレンズ」と発話すると、ウェイクワード検出音が鳴り、AI エージェントがアクティブになる。

**デバイスコンテキストの受け渡し**: AI エージェントへの各リクエストには、§4.8 で定義する `DeviceContext` オブジェクトが自動的に添付される。AI はこれを参照して状況に応じた案内を行う。

**典型的な対話フロー**:

```
ユーザー: 「ヘイレンズ」
  [ウェイクワード検出音]
AI:      「はい、何を撮りますか？」

ユーザー: 「洗い物しようと思う」
  [sherpa-onnx STT → Claude Haiku 意図解析]
AI:      「洗い物のタスクがあります。撮影基準を確認しますか？
           それともすぐ始めますか？」

ユーザー: 「基準教えて」
AI:      「洗い物タスクでは、シンクの前に立って、
           両手で食器を洗う様子を撮影します。
           開始時はシンクに洗い物がある状態、
           終了時は洗い終わった状態にしてください。
           今、端末は縦向きです。このタスクは縦向きで撮影してください。
           準備できたら『始めて』と言ってください。」

ユーザー: 「始めて」
  [タスク確定音]
AI:      「では、両手をカメラに向けてパーにしてください。」
  [→ カメラサブモードへ遷移]
```

**タスクが見つからない場合**:

```
ユーザー: 「庭の草むしりしたい」
AI:      「すみません、草むしりは現在タスクリストにありません。
           今撮影できるタスクは、洗い物、洗濯物畳み、
           料理の下ごしらえ、掃除機がけです。
           どれにしますか？」
```

**デバイス状態に基づく案内**:

```
AI:      「バッテリーが 18% です。30 分の撮影では途中で
           切れる可能性があります。充電しながらの撮影を
           おすすめします。」
```

```
AI:      「今、端末が横向きですが、このタスクは縦向きで
           撮影してください。向きを変えたら教えてください。」
```

### 4.5 ハンバーガーメニューからのタスク選択

ヘッダー右のメニューボタンをタップすると、タスクリストがオーバーレイ表示される。各タスクはタスク名と短い説明を持つ。タスクをタップすると選択され、音声対話で「始めて」と言った場合と同じフローに進む（カメラサブモードへの遷移前に向きの確認等を AI が音声で案内する）。

これはマウント前にタスクを選んでおきたい場合、または音声認識がうまくいかない環境での代替手段である。

### 4.6 対話サブモードでの操作まとめ

| 操作 | 手段 | 結果 |
|------|------|------|
| AI エージェント起動 | 「ヘイレンズ」（音声） | AI が応答待機状態になる |
| タスク選択 | 音声で自然言語指定 / メニューからタップ | タスクが選択される |
| 撮影基準の確認 | 音声で質問 | AI が基準を読み上げる |
| 撮影開始 | 音声で「始めて」等 | カメラサブモードへ遷移 |
| 撮影モード終了 | 音声で「終わり」/ 戻るボタンタップ | ホームタブへ戻る |

### 4.7 撮影完了後の対話サブモードへの復帰

カメラサブモードでの撮影が完了すると、自動的に対話サブモードに戻る。AI は以下のように案内する。

```
  [撮影完了音]
AI:      「撮影完了しました。アップロードを開始します。
           次のタスクはありますか？」

ユーザー: 「洗濯物畳む」
AI:      「洗濯物を畳むタスクですね。準備できたら
          『始めて』と言ってください。」

--- または ---

ユーザー: 「もう終わり」
AI:      「お疲れさまでした。ホームに戻ります。」
  [撮影モード終了音]
  [→ ホームタブへ遷移]
```

### 4.8 DeviceContext

AI エージェントへの各リクエストに添付するデバイス状態オブジェクト。AI はこれを参照して状況に応じた案内を行う。

```typescript
interface DeviceContext {
  // デバイス情報
  device_model: string;          // "iPhone 15 Pro"
  os_version: string;            // "iOS 18.2"
  app_version: string;           // "1.0.0"
  has_lidar: boolean;

  // 現在の状態
  orientation: "portrait" | "landscape_left" | "landscape_right" | "upside_down";
  battery_level: number;         // 0.0 - 1.0
  battery_charging: boolean;
  storage_available_gb: number;
  network_status: "wifi" | "cellular" | "offline";

  // ARKit 状態
  tracking_state: "not_available" | "limited" | "normal";
  hands_detected: {
    left: boolean;
    right: boolean;
  };

  // セッション状態
  selected_task: string | null;
  clips_recorded_this_session: number;
  current_mode: "dialogue" | "camera";
}
```

AI エージェントのシステムプロンプトには、DeviceContext の各フィールドの意味と、フィールド値に応じた案内ルール（バッテリー低下時の警告閾値、向きの推奨等）を含める。タスク定義（タスク名、開始条件、終了条件、推奨 orientation、撮影基準の説明文）もシステムプロンプトに含める。

## 5. 撮影モード: カメラサブモード

### 5.1 進入条件

対話サブモードでタスクが確定し、ユーザーが撮影開始を指示した時点で、カメラサブモードに遷移する。遷移時にモード切り替え音を鳴らす。

カメラサブモードでは音声入力（ウェイクワード検出・STT）は無効になる。音声出力（TTS による AI の読み上げ・効果音・BGM）は有効のまま維持する。操作入力はジェスチャーのみで行う。

### 5.2 画面レイアウト

対話サブモードと同じフルスクリーンカメラプレビューが維持される。視覚的な違いは、会話トーストが消え、録画インジケーター（赤い ● REC マーク + 経過時間）が画面左上に表示される点のみ。画面の向きはカメラサブモード遷移時点で固定され、この向きが録画データの向きになる。

ハンドトラッキングオーバーレイは対話サブモードと同じ。設定でオフにできるが、トラッキング処理自体は常に動作する。

### 5.3 撮影シーケンス

カメラサブモード内の撮影は以下の固定シーケンスで進行する。各ステップの遷移は音で伝える。

#### Step 1: オープンパーム検出

AI の音声案内（「両手をカメラに向けてパーにしてください」）の後、アプリは両手のオープンパーム（開掌）を検出する。42 の手ランドマーク（21 × 2）すべてがフレーム内に 1 秒間継続して検出されると、次のステップに進む。

検出成功時にジェスチャー検出音を鳴らす。

#### Step 2: VLM 開始条件チェック

スナップショットを VLM（Claude）に送信し、選択されたタスクの開始条件への合致を確認する。確認中は待機音（短いループ音）を鳴らす。

合格した場合、合格音を鳴らして Step 3 に進む。不合格の場合、不合格音を鳴らし、AI が音声で理由を伝える（例: 「シンクに洗い物が見当たりません。洗い物をシンクに置いてから、もう一度パーをしてください」）。Step 1 に戻る。VLM 呼び出しが 10 秒以内に応答しない場合、タイムアウトとしてチェックをスキップし Step 3 に進む（AI が「確認できませんでしたが、撮影を開始します」と伝える）。

#### Step 3: カウントダウン

3 秒間のカウントダウン。毎秒カウントダウン音を鳴らす（3, 2, 1）。

#### Step 4: 録画中

カウントダウン完了と同時に録画が開始される。録画開始音を鳴らし、BGM の再生が始まる。

**BGM フィードバック**: 手がカメラのフレーム内に適切に収まっている間は BGM が通常音量で再生される。手がフレームアウトすると BGM がフェードアウトする。手がフレームに戻るとフェードインする。これにより、ユーザーは画面を見ずに手の検出状態を認識できる。

録画中の操作はサムズアップジェスチャーによる停止のみ。音声操作は受け付けない。

#### Step 5: サムズアップ検出

両手のサムズアップジェスチャーが 1 秒間検出されると、録画が停止する。停止音を鳴らし、BGM が停止する。

#### Step 6: VLM 終了条件チェック

終了時のフレームを VLM に送信し、終了条件への達成確度を取得する。確認中は待機音を鳴らす。VLM 呼び出しが 10 秒以内に応答しない場合、タイムアウトとして達成確度を「不明」とし、Step 7 に進む。

#### Step 7: 結果通知と遷移

VLM チェック完了と同時に音声入力を再有効化する（ウェイクワード不要、即座に発話を受け付ける）。AI が達成確度を読み上げた後、ユーザーの発話を待つ。

```
AI:      「撮影完了。達成確度は 85% です。アップロードしますか？
           それとも撮り直しますか？」

ユーザー: 「送って」
  [アップロード開始音]
AI:      「アップロードを開始します。次のタスクはありますか？」
  [→ 対話サブモードへ復帰]

--- または ---

ユーザー: 「撮り直す」
  [破棄音]
AI:      「破棄しました。もう一度始めますか？」
  [→ 対話サブモード復帰、同じタスクで再度 Step 1 から]
```

撮影完了後、「送る/撮り直す」の判断はユーザーの音声で行う（音声操作が再度有効になる）。達成確度の値によって自動棄却は行わない。ユーザーの判断を優先する。

### 5.4 カメラサブモードの操作まとめ

| 操作 | 手段 | タイミング |
|------|------|----------|
| 撮影開始 | オープンパーム 1 秒 | Step 1 |
| 撮影終了 | サムズアップ 1 秒 | Step 5 |
| 送る / 撮り直す | 音声（Step 7 で自動的に音声入力が再有効化） | Step 7 |

## 6. 音の設計

### 6.1 効果音一覧

すべての効果音は短く（0.5〜2 秒）、互いに聞き分けられるように設計する。

| タイミング | 音の種類 | 目的 |
|----------|---------|------|
| 撮影モード進入 | 上昇トーン | モード切り替えの認識 |
| ウェイクワード検出 | 短いチャイム | 「聞いてるよ」の合図 |
| AI 応答開始 | ソフトなクリック | AI が話し始める合図 |
| タスク確定 | 確定トーン（2 音上昇） | タスクが選ばれた認識 |
| カメラサブモード遷移 | モード切り替え音 | 対話→カメラの切り替え認識 |
| ジェスチャー検出（パーム） | 検出音 | 手が認識された合図 |
| VLM チェック中 | 短いループ音 | 処理待ちの認識 |
| VLM 合格 | 合格トーン | 条件クリアの認識 |
| VLM 不合格 | 低いトーン | 条件未達の認識 |
| カウントダウン（3, 2, 1） | カウント音 × 3 | 録画開始の準備 |
| 録画開始 | 開始音 | 録画が始まった認識 |
| 録画停止 | 停止音 | 録画が終わった認識 |
| アップロード開始 | 送信音 | データ送信の認識 |
| 破棄 | 破棄音 | データを捨てた認識 |
| 撮影モード終了 | 下降トーン | モード終了の認識 |
| エラー | エラートーン | 問題発生の認識 |

### 6.2 BGM フィードバック

録画中に再生される BGM は、手のフレームイン状態に連動する。

- **手がフレーム内**: BGM 通常音量で再生。
- **手がフレームアウト**: BGM が 0.5 秒かけてフェードアウト。
- **手がフレームに復帰**: BGM が 0.5 秒かけてフェードイン。

BGM のトラック選択は設定画面で変更可能にする。デフォルトの BGM を用意するほか、ユーザーが無音を選択することもできる（ただし推奨しない旨を表示する）。

## 8. 音声 AI エージェントの技術構成

### 8.1 アーキテクチャ

```
[常時オンデバイス]  sherpa-onnx: ウェイクワード検出（「ヘイレンズ」）+ VAD + STT
                        ↓ テキスト
[クラウド 1 往復]    Claude Haiku: DeviceContext + ユーザー発話 → 意図解析 + 応答生成
                        ↓ 応答テキスト
[オンデバイス]       AVSpeechSynthesizer: テキスト → 音声読み上げ
```

### 8.2 レイテンシ目標

| 処理 | 目標 | 実行場所 |
|------|------|---------|
| ウェイクワード検出 | < 100 ms | オンデバイス |
| STT（発話→テキスト） | < 300 ms | オンデバイス |
| 意図解析 + 応答生成 | < 800 ms | クラウド（Haiku） |
| TTS 開始 | < 100 ms | オンデバイス |
| **発話終了→応答開始** | **< 1,300 ms** | **合計** |

### 8.3 AI エージェントのシステムプロンプト構成

Claude Haiku に渡すシステムプロンプトには以下を含める。

1. **ロール定義**: RootLens の撮影アシスタント。ユーザーのタスク選択を支援し、撮影手順を案内する。
2. **タスクリスト**: 現在有効な全タスクの定義（タスク名、開始条件、終了条件、推奨 orientation、撮影基準の説明文、VLM チェック用プロンプト）。
3. **DeviceContext の解釈ルール**: 各フィールドの意味と、状況に応じた案内ルール（バッテリー 20% 未満で警告、orientation がタスクの推奨と不一致で案内、ストレージ 1 GB 未満で警告、ネットワーク offline で「撮影はできるがアップロードは後で」と案内、等）。
4. **応答スタイル**: 短く、フレンドリーに。1 応答あたり 3 文以内を目安とする。ヘッドマウント中に聞く前提なので、長い文章は避ける。
5. **出力形式**: 応答テキストに加えて、構造化された `action` フィールドを含む JSON で返させる。

```json
{
  "response_text": "洗い物のタスクがあります。撮影基準を確認しますか？",
  "action": {
    "type": "task_matched",
    "task_id": "dishes",
    "await_user_confirmation": true
  }
}
```

action の type:
- `task_matched`: タスクがマッチした。`task_id` を含む。
- `start_recording`: ユーザーが撮影開始を指示した。カメラサブモードへ遷移する。
- `end_session`: ユーザーが終了を指示した。ホームタブへ戻る。
- `info_response`: 情報提供のみ。遷移なし。
- `clarification_needed`: ユーザーの意図が不明。追加質問する。

### 8.4 コスト見積もり

1 インタラクション（ユーザー 1 発話 + AI 1 応答）あたり: 入力 約 2,000 トークン（DeviceContext + タスクリスト + 発話）、出力 約 200 トークン。Haiku 4.5 料金で約 $0.002。

1 撮影セッション（5〜10 インタラクション）あたり: $0.01〜0.02。

## 9. オンボーディング

### 9.1 初回起動フロー

1. **ウェルカム画面**: RootLens の概要説明（3 枚のカルーセル）。
2. **KYC**: 第三者 KYC サービスへの遷移。完了するまで撮影機能はロックされる。
3. **利用規約同意**: 利用規約の 7 項目サマリ（撮影者が同意する内容の要約）を表示し、全文スクロール + チェックボックスで同意を取得する。サマリの内容と利用規約本文の仕様はライセンス仕様書で定義する。
4. **マイク / カメラ権限**: OS の権限ダイアログ。なぜ必要かの事前説明画面を挟む。
5. **チュートリアル**: 初回のみ、撮影モードに入った際にインタラクティブなチュートリアルを表示する。「ヘイレンズ」と言ってみる → タスクを選んでみる → パームを見せてみる → 実際に短い練習撮影をする。

### 9.2 ToS 更新時

ToS の新 version が発行された場合、次回アプリ起動時に §9.1 のステップ 3 のみを再実行する。新 version に同意するまで撮影機能はロックされる。
