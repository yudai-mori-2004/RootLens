# Task 16: 撮影中のリアルタイムガイドと手のサインによる開始 / 停止

## 位置付け

Task 15 で「開始ボタンを押すと ARKit が回って MCAP に書き出される」 ところまでは動いた。 ただし撮影中の画面は黒地に赤い録画マークだけで、 撮影者は自分の手がきちんとカメラに映っているか分からない。 後から品質チェックで「手が映っていない時間が長すぎる」 とはじかれても気づくのが遅い。

本 task は、 撮影者が撮影中ずっと「いま自分の手はカメラに正しく入っている」 と分かる状態を作る。 加えて、 端末に触らずに手のサインだけで録画の開始と停止ができるようにする (= 旧バージョンにあった仕組みを ARKit ベースで復活させる)。

MCAP に書き出される中身は Task 15 と完全に同じで、 手の位置情報などは MCAP に含めない。 撮影中だけ画面上の表示と効果音 / 振動のためにリアルタイムで手を追う。

## 既にあるもの

- Task 15 で ARKit 録画と MCAP 出力が動いている
- 旧コードに、 Vision API の手のポーズ検出 (`app/modules/hand-pose/`) と関節の位置からのサイン判定 (`app/src/domain/gestureDetect.ts`、 両手のパーと両親指立てを判別) がある
- 旧コードに、 撮影フローの状態遷移 (`app/src/domain/captureStateMachine.ts`) がある: 両手パー 1 秒キープ → VLM チェック → カウントダウン 3 秒 → 録画 → 両親指立て 1 秒キープ → 終了処理
- VLM チェックの実装 (`app/src/services/vlmGate.ts`) もある: スナップショット 1 枚をデバイスから直接 Claude API に投げて、 タスクと一致しているか / していないかと理由を返す

これらは現状動かなくなっているが、 本 task で ARKit ベースの新しい撮影パスに移植する。 完了時に旧モジュールは削除する。

## 装着者の手だけを抽出する仕組み

撮影中、 画面に映る手は 3 種類ありうる。

1. 撮影者本人 (= ヘッドマウントを付けている本人) の手
2. 別の人の手 (= 一緒に作業している人、 通行人、 後ろに映る人)
3. 自分の足が「手のように」 誤って検出された場合

このうち本人の手だけを画面表示と効果音の判断対象にする。 ロジックは以下の通り。

**Vision API を 2 つ並列で動かす**

毎秒 15 回、 ARKit から受け取った 1 フレームに対して 2 種類の検出を同時に走らせる。

- 手のポーズ検出 (`VNDetectHumanHandPoseRequest`): 1 フレームから最大 4 つの手を 21 関節で返す
- 身体のポーズ検出 (`VNDetectHumanBodyPoseRequest`): 1 フレームから人物の肩 / 肘 / 手首 / 足首などを返す

**本人の手と他人の手を区別する基準**

頭にカメラを付けて撮影しているとき、 撮影者本人の肩や肘は絶対に画面に映らない (= 自分の身体の一部だから、 視野の外にある)。 逆に、 画面に肩や肘が映っている人がいたら、 その人は撮影者の前にいる別人物だと判断できる。

これを使って次のように分類する。

- 身体のポーズ検出が「画面の中に肩か肘が映っている人がいる」 と返したら、 その人物に紐づく手は他人の手として除外する
- 手のポーズ検出が返してきた手のうち、 上で除外されなかったものを本人の手として扱う
- 身体のポーズ検出が「足首」 を返した位置が、 手のポーズ検出が返した「手」 と画面上で近い (= 画面サイズの 5% 以内) ときは、 その「手」 は足首の誤検出として捨てる

旧提案にあった「手首が画面下半分にあるはず」 「手の見た目が画面の 10% 以上」 のような基準は使わない。 これらは作業姿勢や撮影距離で簡単に当てはまらなくなるため、 採用しない。

**1 フレームだけの判定でブレないようにする**

検出は 1 フレーム単位ではブレるので、 直近 5 フレーム (= だいたい 0.3 秒) の判定をまとめて多数決を取る。 「本人の手が画面に入っている」 状態が「入っていない」 に変わるためには、 連続 3 フレーム分外れた必要がある。 逆に「入っていない」 から「入っている」 に戻るには 1 フレームでいい。 これで、 1 瞬の誤検出で表示が点滅するのを防ぐ。

**処理の負荷を抑える工夫**

身体のポーズ検出は手のポーズ検出より重いので、 常時両方を 15 fps で回すとバッテリーが厳しい。 通常は手のポーズだけを 15 fps で回し、 手のポーズが「本人の手が見当たらない」 を返したフレームでだけ身体のポーズを 1 回追加で走らせる。 これで身体のポーズの実行頻度は全体の 10〜20% に抑えられる。

## 撮影フローの状態遷移

旧バージョンの遷移をそのまま使う。 ARKit ベースの実装に書き換えるだけ。

```
1. 両手パーを 1 秒キープ
   →
2. VLM がスナップショットをチェック
   一致: 次へ
   不一致: 1 に戻る (画面に理由を表示)
   →
3. 3 秒のカウントダウン
   →
4. 録画開始 (ARKit が MCAP を書き始める)
   ↑ 撮影中は本人の手の状態を継続的に画面に表示する
   ↓
5. 両親指立てを 1 秒キープ
   →
6. 録画停止 → VLM が終了時スナップショットをチェック
   →
7. Review 画面へ (Task 15 の出力 MCAP と VLM の結果を渡す)
```

開始のスナップショットは、 状態 2 に入った瞬間の ARFrame.capturedImage を JPEG にして VLM に渡す。 終了のスナップショットも同じで、 状態 5 から 6 に移った瞬間の 1 枚を使う。

VLM の呼び出しは旧実装と同じで、 端末から直接 Claude API を叩く。 API キーをサーバに移す話は別タスクで扱う。

## 撮影中のフィードバックの中身

スマートフォンはネック / ヘッドストラップ装着が前提で、 録画中は撮影者が画面を見られない。 つまり録画中のリアルタイムフィードバックは **音と振動** だけが届く。 画面は撮影開始前の構え確認と、 終了後の Review でしか使われない。

基本姿勢として「正のフィードバックを連続して鳴らす、 状態が悪化したら鳴らさない」 という設計にする。 ピピっと警告音を鳴らすのではなく、 「鳴っているのが普通、 鳴らなくなったら何かおかしい」 と気づかせる方が、 長時間の作業中にイライラさせない。

### 音

録画開始と同時に、 BGM を流し始める。 v1 ではアプリ同梱の短いインスト系ループ音を 1 本固定で使う。 「自分の好きな曲をかけたい」 という拡張は v1.1 で考える (= iOS の MediaLibrary 権限取得が必要、 別タスク)。

BGM の状態:

- 本人の手が片手以上映っている: 通常音量で再生
- 本人の手がフレームから外れた直後: そのまま継続再生 (= 一瞬の出入りで音楽が乱れない)
- 本人の手が 5 秒以上連続してフレームから外れている: 1.5 秒かけてゆっくり消音する (= 「音が消えた」 ことで気付かせる)
- 手が戻ってきた: 0.5 秒かけてゆっくり通常音量に戻す

5 秒待つのは、 ちょっと姿勢を変える / 物を持ち替える程度の一時的な外れで音楽が止まらないようにするため。

### 音声案内 (= 長く外れていたときだけ)

BGM が消音した後、 さらに 3 秒経っても本人の手がフレームに戻ってこなかったら、 軽い音声で 1 回だけ案内する: 「手がフレームから出ています」。 同じ「外れたまま」 の状態が続いている間は再案内しない (= 鳴りっぱなしを避ける)。 手が戻れば、 次に再度長く外れたときにまた 1 回案内する。

音声は AVSpeechSynthesizer で生成する。 BGM とは別チャンネルで小さめの音量で出す。

### 振動 (= ポジティブな確認のみ)

振動は「気持ちのいい確認」 だけに使う。 「外れた」 を振動で知らせない。

- **両手が画面中央付近に綺麗に収まっている瞬間**: 軽い 1 回 (= "well-framed" の確認)
  - 判定基準: 本人の両手の手首ランドマーク (= 関節 0) がどちらも、 画面の中央 60% × 60% の領域に入っている
  - 同じ「良い構え」 状態の間に何度も鳴らないように、 1 回鳴らしたら 3 秒のクールダウンを置く
- **録画開始の瞬間**: 中くらいの強さで 1 回
- **録画停止の瞬間**: 中くらいの強さで 1 回

「外れた」 「片手になった」 等のネガティブ遷移では振動は出さない (= うるさいから)。

振動は `expo-haptics` で出す。 軽いほうは `Haptics.ImpactFeedbackStyle.Light`、 中くらいは `.Medium`。

### 画面 (= 録画前の構え確認用、 録画中は最小)

録画前 (= 両手パーをかざす前):

- カメラプレビューに本人の手のランドマーク (21 関節 × 左右) を重ねて描画
- 画面中央に「両手をフレームの中に入れてください」 とテキスト案内
- 画面中央の中央 60% × 60% の領域を細い枠で表示。 両手の手首がこの枠に入ったら枠を緑色にする
- カウントダウン中は 3, 2, 1 を大きく表示

録画中:

- 画面の隅に小さく REC ドットと経過秒数だけ
- ランドマークオーバーレイは出さない (= 見られないし、 GPU を節約)
- バッジ表示も出さない

これは「録画中の表示」 を実質ゼロに近づけて、 端末の発熱・バッテリーを抑える意味もある。

## 実装する成果物

- `app/modules/arkit-capture/ios/HandTracker.swift` 新規。 ARKit のフレームを 15 Hz で受け取り、 Vision API の 2 種類のリクエストを必要に応じて走らせる
- `app/modules/arkit-capture/ios/WearerHandClassifier.swift` 新規。 手と身体の検出結果を受けて、 本人の手 / 他人の手 / 足の誤検出 を分類する純粋な関数群
- `app/modules/arkit-capture/ios/SnapshotProvider.swift` 新規。 「現在の ARFrame を JPEG として一時ファイルに書き出す」 機能を提供。 VLM チェック呼び出し時に使う
- `app/modules/arkit-capture/ios/ArkitCaptureModule.swift` 拡張。 新しいイベント `onHandTrack` を発火する。 ペイロードは「本人の手の左右別の landmark 21 点」 「フレーム内に何個本人の手が入っているか」 「現在のフレームから判定したサイン (open_palm / thumbs_up / null)」
- `app/src/native/arkitCapture.ts` 拡張。 上の event 型と購読 API を React Native 側に出す
- `app/src/screens/CaptureScreen.tsx` を書き直す。 旧 captureStateMachine の状態遷移を ARKit イベント駆動で動かす。 既存の START / STOP ボタンは残しておく (= 手のサインが効かないときの脱出口として)
- `app/src/components/HandStatusBadge.tsx` を新フィードバック表示に書き直す (= 緑 / 黄 / 赤 + 文字)
- `app/src/components/HandPoseOverlay.tsx` を ARKit イベントの座標系で動くように書き直す
- `app/src/services/realtimeFeedback.ts` 新規。 状態遷移を受けて BGM フェード、 ハプティック発火、 音声案内 (AVSpeechSynthesizer) を一箇所で管理
- 音源を `app/assets/audio/capture-bgm.m4a` として追加 (= 短い静かなインスト系ループ)
- BGM 再生は `expo-av` の `Audio.Sound`、 音量フェードは `setVolumeAsync` を時間補間で呼ぶ
- 旧モジュール `app/modules/hand-pose/`、 旧ファイル `app/src/domain/{gestureDetect,captureStateMachine}.ts`、 `app/src/components/HandStatusBadge.tsx` の旧版、 `app/src/services/vlmGate.ts` の旧呼び出し元、 これらを統合後に削除する

## 完了の定義

1. ARKit ベースで 15 fps の手検出が動いていて、 本人の手と他人の手を分けて画面に出している
2. 両手パーを 1 秒キープ → VLM チェック → カウントダウン → 録画開始、 という遷移が iPhone 12 実機で動く
3. 録画前、 本人の両手の手首が画面の中央 60% 枠に入ると枠が緑になる、 ランドマークが画面に重ねて描画される
4. 録画中、 本人の手が片手以上映っているときは BGM が通常音量で鳴る、 5 秒以上連続で外れると BGM がフェードアウトする、 戻ればフェードインする
5. 録画中、 BGM 消音後さらに 3 秒経っても戻ってこなければ音声案内が 1 回流れる
6. 録画中、 両手の手首が中央 60% 枠にきれいに収まった瞬間に軽い振動が 1 回返る (= ポジティブな確認)
7. 両親指立てを 1 秒キープで録画停止、 VLM 終了チェックが走り、 Review 画面に遷移する
8. 出力ファイル群は Task 15 と同一 (= rgb.mp4 + sensors.jsonl + imu_high_rate.jsonl + camera_intrinsics.json + depth/、 手の情報は端末側ストリームに含めない)
9. 別の人が画面に入って手を振っても、 本人の手の状態として誤判定されない (= 肩・肘の判定が効いている)

## 非スコープ

- 撮影者が自分の好きな曲をかけて録画する (= MediaLibrary 権限取得が必要で、 BGM 体験を一度評価してから機能拡張する。 v1.1 以降)
- データ品質メトリクスの音 / 振動表現 (= 直近 10 秒の手の出現率 %、 IMU の揺れ、 同期率 等を音や触覚で伝える)。 本 task は「いま手が映っているかどうか」 のシンプルなフィードバックに絞る。 v0.2 以降
- 撮影中の VLM 再チェック (= 録画中も継続的に内容を VLM に見せる)
- ハンドサインによる「もう一度」 「タスク変更」 等の高度な操作
- 3D の手の姿勢推定 (WiLoR / MANO)、 後段サーバが担当
