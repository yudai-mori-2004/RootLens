# RootLens License の法的根拠

> 一般読者、 懐疑的な技術者、 AI 企業の法務担当者の三者を想定した公開資料。
> ランディングページに再構成して載せるための原稿。

## 0. 結論を先に

**NFT 自体に法的効力はありません。** 法的効力は、 撮影者が自分の動画について署名した **利用許諾文書** にあります。 NFT は、 その許諾文書が「現時点で誰のものか」 を世界中から検証可能に示すための、 ブロックチェーン上の **記号** にすぎません。

たとえるなら、 **映画館やコンサート会場の入場券** のようなものです。 入場券そのものはただの紙切れ (あるいは QR コード) で、 それ単独では何の権利も生み出しません。 法的な意味を持つのは会場が定める **入場規約** のほうで、 「この入場券を持っている人は、 この日のこの席で、 こういう条件で観覧してよい」 と規約が定めている。 入場券は単に「いま、 その権利を誰が持っているか」 を示す引換証にすぎません。

友達に入場券を譲れば、 友達が観覧する権利を得ます。 紙切れに魔法の力が宿るからではなく、 「**入場券を持っている人 = 観覧してよい人**」 と規約が定めているからです。

RootLens の NFT も同じ仕組みです。 NFT 自体に法的効力はなく、 法的効力は NFT が指す **利用許諾文書** にあって、 文書が「**現在この NFT を保有している人 = 動画を利用してよい人**」 と定めています。 NFT が譲渡されると新しい保有者が権利を得る、 という性質も入場券と同じです。

この設計は新しい発明ではありません。 著作権の世界で 30 年以上使われてきた仕組み (オープンソースソフトウェアのライセンス、 クリエイティブ・コモンズ・ライセンス 等) を、 NFT という新しい識別技術に乗せただけです。

以下、 用語を順に整理し、 各段階の法的根拠を一次資料で示します。

## 1. まず用語の定義

専門用語が登場するたびに混乱しないよう、 先に整理します。 後の議論で略称を使うときは、 必ずこの表の左側を意味します。

| 略称 / 専門用語 | 平易な日本語 |
|---|---|
| **著作権者** | 動画を撮影した本人。 著作権は撮影した瞬間に自動発生する (著作権法第 17 条) |
| **著作権** | その動画を独占的に利用してよい権利 |
| **利用許諾 (ライセンス)** | 「これを満たす人は私の動画を使ってよい」 という、 著作権者からの宣言 |
| **再許諾 (サブライセンス)** | ライセンスをもらった人が、 さらに別の人にライセンスを再付与すること |
| **利用規約 (Terms of Service)** | サービスを使うときに利用者が同意する文書 |
| **クリックスルー同意** | 「同意します」 ボタンを押す形式の合意。 一般的なウェブサービスで広く使われる |
| **NFT** (Non-Fungible Token) | ブロックチェーン上の一意な記号。 単なる識別子 |
| **Root NFT** | RootLens で、 動画 1 本に 1 つ発行される識別子 NFT |
| **License NFT** | RootLens が発行する、 「この NFT の保有者は動画の利用許諾を受けている」 を示す NFT |
| **代理人 (delegate)** | 撮影者から「あなたが代わりに再許諾を発行してよい」 と委任された主体。 RootLens の運営アカウント |
| **ステーキング** | 撮影者が自分の Root NFT に「この代理人に再許諾発行権を委任します」 と公開記録する操作 |
| **スマートコントラクト** | ブロックチェーン上で自動実行されるプログラム。 RootLens では License NFT の発行と USDC 決済を一つの不可分な操作として実行する |
| **USDC** | 米ドルに 1 対 1 で連動するステーブルコイン (= 価格変動の少ない暗号資産)。 License NFT 購入の決済通貨 |
| **メタデータ** | NFT に紐づく付随情報 (作成日、 参照先 URL、 識別子 等)。 License NFT のメタデータには利用許諾文書の URL が記録される |
| **sha256** | 暗号学的ハッシュ関数 (ある入力から固定長の値を計算する関数で、 同じ入力からは必ず同じ出力、 出力から入力は逆算できない)。 文書の改ざん検知に使う |
| **販売規約 (Terms of Sale)** | License NFT を購入する側 (AI 企業) が同意する、 買い手側義務 (通知義務、 制裁対象者でない旨の条件、 改変制限 等) を定めた文書 |

## 2. 仕組みの全体像

RootLens のライセンス発行は、 4 つのステップで成立します。

**ステップ 1**: 撮影者が利用規約に同意する (チェックボックス + 「同意します」 ボタン)。 規約には「私は RootLens に対し、 私の動画について再許諾を発行する権限を与えます」 という条文が含まれる。

**ステップ 2**: 撮影者がアプリで動画を撮影し、 Root NFT が発行される (= ブロックチェーン上に動画の識別子が記録される)。

**ステップ 3**: 撮影者が Root NFT をステーキングする (= 「RootLens 運営アカウントを代理人に設定します」 とブロックチェーン上で記録)。

**ステップ 4**: AI 企業が代金 (USDC) を払い、 RootLens の代理人としての署名を伴ってスマートコントラクトを実行する。 AI 企業に License NFT が発行され、 そのメタデータには「この動画について、 こういう条件で利用してよい」 と書かれたライセンス文書の URL が記録される。

```
撮影者
  │ 利用規約への同意で、 RootLens に「再許諾発行権」 を授権
  ↓
RootLens (= 代理人)
  │ AI 企業から代金を受け取り、 スマートコントラクトで License NFT 発行
  ↓
AI 企業 (= License NFT 保有者)
   License NFT のメタデータが指すライセンス文書に従って動画を利用
```

## 3. 各ステップの法的根拠

### 3.1 撮影者の利用規約同意は法的に有効か

**米国の現代基準**: 第二巡回区連邦控訴裁判所 *Meyer v. Uber Technologies, Inc.*, 868 F.3d 66 (2d Cir. 2017) が、 クリックスルー同意の現代的な有効性基準を確立しています。 同判決は「合理的な利用者が認識できる明瞭性で規約を提示し、 利用者が明示的な操作で同意意思を示せば、 拘束力ある合意が成立する」 と判示しました。 連邦の各巡回区裁判所が同判決を踏襲しており、 米国では実質的に確立した基準です。

**日本の法的根拠**: 民法第 548 条の 2 から第 548 条の 4 (2020 年改正で追加された「定型約款」 規定) が、 大量の取引で使われる利用規約の効力を定めています。 同条は、 利用規約があらかじめ準備され、 相手方が「同意する旨の意思表示」 をしたとき、 個別条項についても合意が成立するとしています (第 548 条の 2 第 1 項)。

加えて、 民法は契約成立に書面を要求しません (= 諾成主義、 第 522 条)。 クリックスルー方式での同意は、 通常の契約成立要件を満たします。

RootLens は同意成立時に以下を記録します。

- 同意した利用規約のバージョン
- 利用規約全文の改ざん検知用ハッシュ値 (sha256)
- 同意した撮影者の識別子 (ブロックチェーンウォレットのアドレス)
- 同意した時刻
- 同意時の IP アドレスとブラウザ情報

これは一般的なウェブサービス (Google、 Microsoft、 Apple、 銀行アプリ、 通販サイト) と同じ記録形式です。

### 3.2 「License NFT を保有する人 = ライセンシー」 は法的に成立するか

これがこの設計のコアです。 法的根拠は複数の層で支えられています。

#### 米国法

**米国著作権法第 204 条 (a)** によれば、 著作権の **譲渡** には署名された書面が必要です。 ただし、 **非排他的ライセンス** (= 同じ著作物を複数人に与えてよいライセンス) は同法第 101 条の「著作権の譲渡」 の定義から明示的に除外されており、 書面なし (口頭または行為による黙示も可) で成立します。

*Jacobsen v. Katzer*, 535 F.3d 1373 (Fed. Cir. 2008) では、 連邦巡回区控訴裁判所が、 オープンソースソフトウェアの Artistic License について、 「公開された一方的ライセンスでも、 そこに付された条件 (帰属表示の義務、 改変告知の義務 等) は著作権上の条件として有効で、 違反は著作権侵害となる」 と判示しました。 オープンソースやクリエイティブ・コモンズ系列のライセンスが米国で広く運用されているのは、 この判決が直接の根拠です。

米国法では、 著作権者が「この License NFT を保有する人」 をライセンシーと定義する非排他的ライセンスは、 第 204 条の例外規定と Jacobsen の枠組みで成立し、 違反は著作権侵害として救済可能です。

#### 日本法

**著作権法第 63 条 (利用許諾)** によれば、 著作権者は他人にその著作物の利用を許諾でき (第 1 項)、 許諾を受けた者は許諾された範囲内で利用できます (第 2 項)。 許諾の方法に書面や登録の要求はありません。

**著作権法第 63 条の 2 (2020 年改正で追加された当然対抗制度)** によれば、 利用権 (= 著作物利用許諾を受けた地位) は、 **その後に著作権が第三者に譲渡された場合でも、 譲受人に当然に対抗できる** (= 登録不要で守られる) ようになりました。 これは NFT 譲渡型のライセンスにとって決定的に重要です。 撮影者がもし将来著作権を別の人に譲渡しても、 既に発行された License NFT の保有者の利用権は守られます。

#### 学術モデルとイーサリアム標準への合流

NFT を「ライセンシーの識別子」 として用いる法理は、 二つの独立した出典が同じモデルに収斂する形で支えられています。

- James Grimmelmann (Cornell Tech / Cornell Law) が IC3 (Initiative for Cryptocurrencies and Contracts) で 2022 年に公表した *The Token-Bound NFT License*。 「NFT 保有者をライセンシーとして識別する非排他的ライセンス」 のドラフト枠組みを学術的に提示。
- イーサリアム標準規格 **ERC-5218 (NFT Rights Management)** (James Grimmelmann、 Yan Ji、 Tyler Kell の共著、 2022 年公表)。 「`licenseURI()` でライセンス文書 URL を返す」 「`createLicense() / revokeLicense()` で発行と取り消しを記録する」 等のインターフェースを定める。

両者は独立した成果物ですが、 「NFT のメタデータがライセンス文書を指す + ライセンス文書側がライセンシーを **現 NFT 保有者** と定義する」 という同じトークン束縛モデルに帰着します。 Story Protocol を含む複数の商用実装が ERC-5218 およびその派生パターンで実装されています。 Andreessen Horowitz の "Can't Be Evil" シリーズは契約モデル (= 「あなたはこの規約に同意する」) を採用しており、 RootLens の一方的許諾モデルとは構造が異なる別系統です。

RootLens のメタデータ構造は ERC-5218 と同型です。 イーサリアムではなく Solana 上での実装ですが、 法理と実装パターンは完全に一致しています。

ただし、 これらはあくまで学術的に提案されたドラフトと業界標準にすぎません。 まだ世界のどの裁判所も「NFT 保有 = ライセンシーの識別」 という条項を実際に司法判断で確認していません。 我々はこの点を正直に認識しており、 ライセンス文書の文言は Creative Commons 4.0 International のような数十年運用実績のあるパターンを基にしています。

### 3.3 ライセンス文書とブロックチェーンの結合 (改ざん検知)

License NFT のメタデータにはライセンス文書の URL が記録されます。 ただ単に URL を載せるだけだと「文書を書き換えれば履歴を改ざんできる」 のではないかと疑われます。 RootLens は二段階の改ざん検知を仕込んでいます。

**第 1 層**: スマートコントラクトが、 License NFT を発行する時に「この NFT は、 Root NFT (= 動画識別子) X に紐づきます」 という参照を、 NFT メタデータの URL 末尾に自動付加します。 メタデータはブロックチェーンのハッシュ計算に取り込まれ、 発行後の改ざんが暗号学的に不可能になります。

**第 2 層**: ライセンス文書本体の URL の中に、 文書全体の sha256 ハッシュ値を含めます。 例:

```
https://rootlens.io/licenses/commercial-v1/<sha256-hash-of-the-file>.json
```

第三者は URL から文書を取得し、 文書のハッシュ値を計算し、 URL に含まれるハッシュ値と一致するか確認できます。 これにより、 RootLens 側が後からこっそり文書を差し替えることは検知可能になります。

## 4. なぜこの仕組みが全世界で通用するか

### 4.1 著作権の国際的基盤 — ベルヌ条約

**ベルヌ条約 (Berne Convention for the Protection of Literary and Artistic Works, 1886 年制定)** は、 著作権の国際的な最低保護水準を定める条約で、 現在 182 ヵ国が締約しています (世界知的所有権機関 WIPO 公表)。 同条約第 5 条第 2 項は、 著作権の享受および行使にいかなる方式 (= 登録、 表示、 通知) も必要としないと定めています。 撮影した瞬間に著作権が世界中で発生し、 同時に「他人に許諾できる権利」 も発生します。

つまり、 撮影者が「この条件で誰かに使わせる」 と意思決定する権利は、 ベルヌ条約 182 締約国で共通に認められています。

### 4.2 紛争解決の国際的基盤 — ニューヨーク条約

ライセンス文書の準拠法と紛争解決機関に何を選んだとしても、 紛争が起きたときに判決を執行できる地理的範囲が問題になります。 これに対処するのが **外国仲裁判断の承認及び執行に関する条約 (ニューヨーク条約、 1958 年)** で、 現在 172 ヵ国が締約しています (国際連合国際商取引法委員会 UNCITRAL 公表)。 ある国の仲裁機関が下した判断は、 同条約締約国 172 ヵ国どこの裁判所でも執行可能です。

RootLens のライセンス文書はすべて **シンガポール法を準拠法** とし、 **シンガポール国際仲裁センター (SIAC)** を紛争解決機関に指定します。 ニューヨーク条約 非締約国 (台湾等の少数の管轄) では現地で個別の手続が必要となる旨も、 ライセンス文書に明示します。

シンガポールが選ばれる理由は次のとおりです。

- **中立地**: 米国、 日本、 EU、 中国のいずれから見ても「特定相手に有利」 にならない。
- **国際仲裁の世界的中心**: SIAC は ICC (パリ)、 LCIA (ロンドン) と並ぶ仲裁機関で、 実務経験豊富な仲裁人プールがある。
- **コモンロー基盤**: 英米企業に馴染みのある法体系。
- **ニューヨーク条約締約国**: SIAC の判断は 172 ヵ国で執行可能。

これは Netflix / Spotify / AWS が国境を越えてサービスを提供するときに採用しているのと同じパターンです。

### 4.3 個別国の事情 — 強行法規だけが当事者合意を上書きする

ライセンス文書で「シンガポール法に従う」 と定めたとしても、 各国の **強行法規** (= 当事者の合意で排除できない法) だけは当事者合意を上書きします。 具体的には次のとおりです。

- EU の **一般データ保護規則 (GDPR)**: EU 居住者の個人データ処理についての義務は当事者合意で排除できません。
- 各国の **著作者人格権** (= 創作者の人格的利益に関する権利): 多くの大陸法系国では譲渡できません (詳細は §5)。
- 各国の **消費者保護法**: ただし RootLens の取引相手は AI 企業 (= 商人) なので、 消費者法が介入する余地は実質的に小さくなります。

これらは「RootLens のスキームが法的に怪しい」 のではなく、 地球上のあらゆるグローバルサービスが共通に直面する問題と同じです。

## 5. 著作者人格権の扱い — AI 学習で改変が起きる場合

これは正直に書く必要のある重要な論点です。

ベルヌ条約第 6 条の 2 が定める **著作者人格権** (= 著作物について創作者が持つ「同一性保持権」 「氏名表示権」 「公表権」) は、 多くの大陸法系国 (日本、 フランス、 ドイツ) では譲渡不能かつ放棄不能とされています。 日本では著作権法第 59 条が「著作者の一身に専属し、 譲渡することができない」 と明文で定めています。

AI 学習で動画から派生物を作る場合、 「同一性保持権」 (= 著作物を勝手に改変されない権利) や「氏名表示権」 (= 著作者として表示される権利) に触れる可能性があります。

RootLens の対応として、 利用規約に **「著作者人格権の不行使特約」** を組み込みます。 これは「著作者人格権を放棄する」 のではなく、 「契約所定の範囲内では行使しない」 と撮影者があらかじめ約する条項です。 日本では、 音楽業界 (JASRAC 関連契約)、 映像業界、 出版業界で広く採用されてきた防衛的な定型条項で、 下級審判例で「通常の利用行為については有効、 ただし著作物の本質を著しく害する場合は除く」 という枠組みが受け入れられています (代表例として 東京地方裁判所 平成 13 年 7 月 2 日判決 宇宙戦艦ヤマト事件。 不行使特約の判例としてはほかに東京地裁 平成 16 年 11 月 12 日、 知財高裁 平成 18 年 10 月 19 日 計装士講習会資料事件 等)。

ただし、 これらは地方裁判所 / 高等裁判所レベルの判決であって、 最高裁判決ではありません。 RootLens の利用規約の最終文言は、 日本の知的財産専門法律事務所のレビューを経たうえで確定します。

## 6. 撮影者の身元 — 本人確認と公開仮名性の両立

ブロックチェーン上では撮影者はウォレットアドレスという仮名で表現されます。 これだけだと「撮影者が誰か特定できない、 なりすましされたら追えない」 という懸念が生じます。

RootLens の設計は次のとおりです。

- **撮影者登録時に本人確認 (KYC) を必須にします**。 第三者の本人確認事業者を経由して身元を確認・記録します。
- 本人確認情報は **RootLens 内部のみで暗号化して保管します**。 ブロックチェーン上にも公開 API にも出しません (= 撮影された動画と個人の身元が公開の場で結びつくことはありません)。
- 法的紛争・不正調査・税務報告 等の正当な根拠がある場合に限り、 RootLens 側でウォレットアドレスと身元情報を結びつけます。

この二層構造により、 以下が同時に成立します。

- **AI 企業にとっての安心材料**: 身元が確認された撮影者が著作権者として表明していること (= 仮名のままだと表明・保証が機能しない懸念がありましたが、 本人確認で身元が裏側で取れているので、 万一の表明違反時にも責任追及が可能です)。
- **撮影者のプライバシー**: 「私は誰か」 が公開されることはありません (= 動画と本名が公開の場で結びつかない)。
- **第三者検証性**: ライセンス連鎖の検証 (仕様書 SPECS_JA.md §4.4.6 参照) は引き続きウォレットアドレスのみで動きます (= 第三者は撮影者の身元を知らずに検証できる)。

RootLens は本人確認データを保管する以上、 個人情報の管理者として個人情報保護法・GDPR 等の義務を負います (= 適切な暗号化、 アクセス制限、 漏洩時の通知、 削除要求への対応)。 これらの管理体制を別途整備し、 監査の対象とします。

## 7. 買い手の安心 — 補償と通常デューデリジェンス免除

ライセンスを購入する AI 企業の本音は「訓練データで訴えられたくない」 です。 もし「ライセンスを買っても自己責任、 個別動画の事前審査は買い手側で実施せよ」 と言われたら、 ライセンスを買う動機が消えてしまいます。 RootLens は三層の責任分担で買い手の安心を直接の価値提案にします。

### 7.1 三層責任の流れ

| 層 | 担い手 | 内容 |
|---|---|---|
| 第 1 層 | 撮影者 | 利用規約で「自分が本コンテンツの著作権者であり、 第三者の知財・肖像権・パブリシティ権は含まれていない」 と表明・保証。 違反時には損害賠償の責を負う。 |
| 第 2 層 | RootLens | 本人確認で撮影者の身元を把握しているため、 撮影者が表明・保証に違反した場合に経済的な責任追及が可能。 加えて、 機械による撮影内容の自動判定 (画像言語モデルによる事前審査) で明らかな第三者著作物を発行前に弾く合理的な努力を実施。 上記をもとに、 買い手に対して限定的な補償を提供。 |
| 第 3 層 | 買い手 (AI 企業) | 通常の商用利用 (= 集合的な AI 学習を含む) の範囲では、 動画ごとの個別事前審査義務を負わない。 ただし、 第三者著作物が含まれていると **実際に知った場合** は RootLens に通知する義務を負う (= 受動的な通知のみで足り、 「気付くべきだった」 という意味での認識 (構成的認識) までは求めない)。 |

### 7.2 補償の内容 (二段階のティア制)

買い手に対し第三者から著作権・肖像権・パブリシティ権の訴訟が起こされ、 それが許諾者 (撮影者) の表明・保証の範囲内であれば、 RootLens は補償します。 補償は **標準プラン (Standard)** と **大口契約プラン (Enterprise)** の二段階で提供します。

**標準プラン (= 全買い手向けの既定)**

- 当該ライセンス料金の払い戻し。
- 買い手が RootLens の訴訟引受前に合理的に支出した防御費用。
- 上限額: 1 件の訴訟あたり 5 万米ドル、 同一買い手 × 同一 Root NFT × 1 年あたり合計 25 万米ドル。 これは学習データのライセンス業界で見たとき、 Shutterstock の Standard ライセンス (画像 1 点あたり数千ドル〜1 万ドル規模) と Enhanced ライセンス (数万〜25 万ドル規模) の間にあたる中位水準です。

**大口契約プラン (= 大口買い手向け、 別途個別契約)**

- 標準プランの上限を超える補償。
- AI モデルの再学習費用も補償対象に含める (= 学習データのライセンス業界に固有の主要な損害類型)。
- 上限額は買い手のライセンス購入規模・利用形態に応じて個別に交渉します。
- RootLens 側で知的財産権侵害損害保険による裏付けを取得することが提供の条件。 提供開始時期は事業段階に応じます (= 初期段階では標準プランのみ、 事業拡大に伴い大口契約プランを解禁)。

「全買い手に高額の補償を約束する」 ことは、 創業期段階の RootLens が自己資金で履行できる範囲を超えます。 大口買い手向けの補償拡張は、 知的財産権侵害損害保険の取得と組み合わせて提供する設計です。

### 7.3 補償対象外となる場合

以下は補償の対象外とします。

- 買い手がライセンスの定める範囲を超えて利用した場合。
- 買い手が問題の存在を **実際に知っていた** のに RootLens に通知しなかった場合 (= 「気付くべきだった」 という構成的認識までは採用しません。 採用してしまうと、 買い手側に動画 1 本ごとの能動的な事前審査義務を実質的に発生させてしまうため)。
- 買い手がライセンス対象コンテンツを改変した結果として発生した訴訟。

## 8. 契約構造 — 一方的許諾文書と販売規約の二層

純粋な一方的許諾文書 (= 著作権者が一方的に「この NFT を保有する人は使ってよい」 と宣言する文書) の中に、 買い手側の義務 (通知義務、 制裁対象者でない旨の条件、 補償対象外項目 等) を書き込むと、 買い手はその義務に同意したわけではないため、 当該義務部分に法的拘束力を持たせられない懸念があります。

これを構造的に回避するため、 RootLens は二層構造を採用します。

- **販売規約** — 買い手側の義務 (通知義務、 制裁対象者でないことの確認、 改変の制限 等) を載せる文書。 License NFT 購入フローで買い手が明示的に同意します (= クリックスルー方式の同意画面に加え、 サーバ側で同意ログを記録)。
- **ライセンス文書本体** — 著作権の許諾そのもの。 一方的な許諾として License NFT のメタデータが指す URL に格納し、 NFT を譲渡したとき新しい保有者にも自動でライセンスが引き継がれます。

この構造により、 著作権許諾本体は学術モデル (Grimmelmann 型) の一方的許諾を維持しつつ、 買い手側の義務については独立した契約として拘束力を確保します。

## 9. 事業継続性 — RootLens が事業を続けられなくなった場合

既に発行された License NFT は、 ブロックチェーン上に不変な記録として永続します。 RootLens の存続有無に関わらず、 保有者の利用権は保たれます (= 著作権者である撮影者の一方的許諾が法的根拠であり、 RootLens は仲介者にすぎないため)。

RootLens が事業継続不能となった場合に備え、 代理人 (delegate) の権限を引き継ぐ計画 (= 後継となるサービス提供者、 DAO 化、 撮影者本人を代理人として再設定する 等の選択肢) を利用規約・販売規約にあらかじめ定めておきます。 大口契約プランの買い手向けには、 補償義務の引き継ぎ先 (= 後継主体への譲渡、 又は保険による補填) を個別契約で取り決めます。

技術的な詳細は仕様書 (SPECS_JA.md §11.3 参照) で定義しています。

## 10. 日本での AI 学習例外と RootLens の市場効果

これは多くの読者が見落とす重要な点です。

**著作権法第 30 条の 4 (2018 年改正で追加された AI 学習例外)** は、 著作物について「情報解析の用に供する場合」 (= AI 学習を含む) は、 著作権者の許諾なく利用してよいと定めます。 一見すると、 「日本では AI 学習にライセンスを買う必要がないのでは」 と読めます。

しかし同条には **但し書** (= 例外の例外) があります。

> 「当該著作物の種類及び用途並びに当該利用の態様に照らし著作権者の利益を不当に害することとなる場合は、 この限りでない。」

**2024 年 3 月の文化庁公式見解** (= 文化審議会著作権分科会法制度小委員会「AI と著作権に関する考え方について」) は、 この但し書の適用基準について次のように述べています。

> 「本来、 情報解析用としてのライセンス市場が成り立っているデータベースについて、 [無許諾で利用すると] ライセンス市場と衝突し、 著作者のライセンス料による利益を阻害することになる」

つまり、 RootLens のような AI 学習用ライセンス市場が成立しているコンテンツ領域では、 同じコンテンツを無許諾で取得・収集する行為は第 30 条の 4 の自由利用から外れるという見解が、 行政庁の公式立場です。

文化庁の見解は行政解釈であって、 裁判所を直接拘束するものではありません。 ただし、 著作権を所管する省庁の最新公式見解として、 「ライセンス市場の存在が但し書 該当を引き起こす」 という論理構成は、 法学者の多数説とも整合しています。

つまり、 RootLens がライセンス市場を作ること自体が、 撮影者のコンテンツへの無許諾収集を第 30 条の 4 の自由利用から除外する法的効果を持ちます。

### 10.1 米国 / EU の状況

**米国**: 第 30 条の 4 のような明示的な AI 学習例外はなく、 著作権侵害に対する防御は「フェアユース」 法理に拠るしかありません。 2024 年から 2026 年にかけて、 *Andersen v. Stability AI* (米国カリフォルニア州北部地区連邦地裁)、 *The New York Times v. OpenAI* (米国ニューヨーク州南部地区連邦地裁)、 *Authors Guild v. OpenAI* (同) など多数の訴訟が係属中で、 主要な請求はいずれも訴え棄却の申立てを免れて本案審理に進んでいます。 AI 企業側のフェアユース防御が確立しているとは言い切れない状況です。

**EU**: AI 規則 (Regulation (EU) 2024/1689) 第 53 条第 1 項 (c) が、 汎用 AI モデル提供者に「著作権法の遵守方針を策定する義務」 を課しています。 同時にデジタル単一市場における著作権指令 (Directive (EU) 2019/790) 第 4 条第 3 項は、 著作権者の明示的な留保表明 (= 機械可読な利用停止表明) がある場合、 AI 学習目的の利用は許されないとしています。 つまり EU 圏では、 著作権者が明示的に留保を表明すれば AI 学習からコンテンツを除外できます。

これらの状況下で、 AI 企業 (= License NFT の買い手側) は、 「無断で取得して訴訟リスクを抱える」 か「ライセンスを買って法的不確実性をゼロにする」 かの選択を迫られています。 市場は明らかに後者に動いており、 OpenAI と News Corp / AP / FT / Axel Springer 等のライセンス契約締結はその表れです。

## 11. 何が確定で、 何が未確定か

正直に区分します。

### 11.1 確定しているもの (= 法令 / 上級審判例 / 国際条約で裏付けされる)

- 著作権者が自分の著作物について非排他的ライセンスを **書面なしで** 与えられること。
- そのライセンスが世界の主要国で執行可能であること (ベルヌ条約)。
- クリックスルー方式での同意が、 適切な提示と明示的な同意操作を伴えば法的に有効であること (米国 *Meyer v. Uber*、 日本 民法 548 条の 2)。
- シンガポール法と SIAC 仲裁の組み合わせが、 ニューヨーク条約 172 締約国で執行可能であること。
- ライセンスを受けた人の地位が、 著作権者が後に著作権を譲渡しても守られること (日本 著作権法 63 条の 2 = 当然対抗制度)。

### 11.2 まだ判例で確認されていないもの (= 学術的提案 / 行政解釈 / 業界実務段階)

- 「License NFT を保有する人 = ライセンシー」 という識別方法が、 実際の紛争で裁判所により実体的に認められるか。 学術的に支持されていますが、 まだ世界のどの裁判所も実際の紛争で確認していません。 ただし、 License NFT が単独で法的効力を持つ必要はなく、 著作権法 63 条 + ライセンス文書の文言 + クリックスルー同意 + ハッシュ結合の組合せで、 NFT をライセンシーの識別子として使う構成は既存の確立した法理の組合せにすぎません。
- 著作者人格権 不行使特約の最高裁レベルの判断。 下級審判例と業界実務で機能していますが、 最高裁判決はまだありません。
- 日本 第 30 条の 4 但し書 の司法による直接確認。 文化庁の見解はありますが、 裁判所による直接判断はまだありません。

これらの「未確定」 領域は、 RootLens 固有のリスクではなく、 NFT / AI / ブロックチェーン全般の発展期にある法分野で誰もが直面する状況です。 我々はそのリスクを正直に開示し、 ライセンス文書の文言は専門法律事務所のレビューを経て、 確定した法理だけで最大限の保護が成立するよう設計しています。
